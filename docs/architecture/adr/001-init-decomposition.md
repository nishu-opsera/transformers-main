# ADR 001: Domain sub-registry architecture for `transformers.__init__`

| Field | Value |
|-------|-------|
| Status | Accepted (ForgeScore modernization WO-009) |
| Date | 2026-05-26 |
| Work order | WO-009 |

## Context

The root `transformers.__init__` re-exports 400+ symbols through a single `_LazyModule` and flat
`_import_structure`. ForgeScore reports a fan-in of ~6,597 on the package root, making every
registration a global coupling point. The modernization program (REQ-011) requires decomposing
imports into domain-scoped sub-registries (NLP, Vision, Audio, Multimodal) **without** breaking
existing public import paths such as `from transformers import BertModel`.

Circular dependency work (WO-006–WO-008) must reduce top-level cycles before the root `__init__`
can safely import domain facades.

## Decision

1. **Domain classification** — Every `model_type` in `CONFIG_MAPPING_NAMES` is assigned a
   `primary_domain` and optional `secondary_domains` in
   `src/transformers/models/domain_registry.json` (generated by `utils/generate_domain_registry.py`).

2. **Sub-registry modules** — Introduce lazy domain entry points (implementation in WO-010/WO-011):
   - `transformers.domains.nlp`
   - `transformers.domains.vision`
   - `transformers.domains.audio`
   - `transformers.domains.multimodal`

   Each domain module owns a domain-local `_import_structure` fragment. The root `__init__` composes
   these fragments instead of listing every symbol directly.

3. **`_LazyModule` extension** — Add a helper `merge_import_structures(*fragments)` that deep-merges
   domain dicts into the existing root structure. Root `__init__` continues to expose the union of
   all domains so **no public import path changes**.

4. **Cross-domain models** — Models such as `clip` and `llava` use `primary_domain: multimodal`
   with `secondary_domains` listing additional modalities. They are registered in the multimodal
   facade and re-exported from the root; domain-specific facades may alias them for discoverability.

5. **Backward compatibility** — Existing `from transformers import X` and
   `from transformers.models.<name> import Y` remain valid. New recommended paths
   (`from transformers.domains.nlp import BertModel`) are additive.

## Alternatives considered

| Alternative | Why rejected |
|-------------|--------------|
| Break imports in a major release | Violates modernization constraint of preserving public API |
| Per-model packages on PyPI | Out of scope; internal module structure only |
| Single flat registry with tags only | Does not reduce fan-in or enable lazy domain loading |

## Consequences

- **Positive:** Lower root fan-in over time; domain teams can own registration lists; aligns with
  import-time reduction goals (WO-004).
- **Negative:** Two sources of truth until generation is fully automated — mitigated by
  `generate_domain_registry.py` and CI checks in WO-010+.
- **Follow-up:** WO-010 (NLP/Vision registries), WO-011 (Audio/Multimodal), WO-026
  (characterization tests), WO-028 (rollback procedures).

## Validation

- `domain_registry.json` must contain exactly `len(CONFIG_MAPPING_NAMES)` entries.
- Run `PYTHONPATH=src python utils/generate_domain_registry.py --check` in CI.
- Manual review: all `secondary_domains` for multimodal models include the expected modalities.
